## 2. Теория и аналитический вывод сложности

### 2.0. Рекурсия и её стоимость

Рекурсивная функция вызывает саму себя на меньшем входе и останавливается на **базовом случае**. Каждый незавершённый вызов хранит свой кадр в стеке вызовов, поэтому, кроме времени, у рекурсии есть **память**: она равна максимальной глубине вложенности, а не общему числу вызовов. В CPython глубина ограничена (по умолчанию 1 000) — это практическое ограничение линейной по глубине рекурсии.

Время рекурсивного алгоритма выводится из **рекуррентного соотношения**: время на входе n выражается через время на меньших входах.

### 2.1. `factorial` — факториал

```
T(0) = c₀
T(n) = T(n−1) + c   →   T(n) = c·n + c₀   →   Θ(n)
```

n + 1 вызовов, в каждом одно умножение и сравнение. Глубина рекурсии n + 1, поэтому память **Θ(n)** — в отличие от итеративного цикла с O(1).

Оговорка: оценка Θ(n) верна в модели RAM, где умножение стоит O(1). В Python n! быстро становится длинным числом (20! уже не помещается в 64 бита), и стоимость умножения растёт с длиной числа; для больших n реальное время растёт быстрее линейного.

*Инвариант:* `factorial(k)` возвращает k! для всех k < n — тогда n·(n−1)! = n!.

### 2.2. `fib_naive` — наивная рекурсия Фибоначчи

Число вызовов C(n) удовлетворяет соотношению:

```
C(0) = C(1) = 1
C(n) = 1 + C(n−1) + C(n−2)
```

Прибавив 1 к обеим частям: C(n) + 1 = (C(n−1) + 1) + (C(n−2) + 1) — то есть C(n) + 1 подчиняется рекурсии Фибоначчи с начальными значениями 2, 2 = 2·F(1), 2·F(2). Отсюда **точная формула**:

```
C(n) = 2·F(n+1) − 1
```

F(n) растёт как φⁿ/√5, где φ = (1 + √5)/2 ≈ 1,618 — золотое сечение. Поэтому время **Θ(φⁿ) ≈ Θ(1,618ⁿ)**; часто пишут верхнюю оценку O(2ⁿ) — она верна, но не точна. Память — Θ(n): в любой момент активна только одна ветвь дерева вызовов глубиной n.

Причина экспоненты — **перекрывающиеся подзадачи**: fib(n−2) вычисляется и внутри fib(n−1), и отдельно; fib(n−3) — уже трижды, и так далее.

### 2.3. `fib_memo` — Фибоначчи с мемоизацией

**Мемоизация** — сохранение результатов уже решённых подзадач в словаре; повторный вызов возвращает готовое значение за O(1). Каждое значение k = 2…n вычисляется ровно один раз и порождает два вызова (k−1 и k−2); все повторные вызовы попадают в словарь сразу. Итого:

```
C(n) = 1 + 2·(n − 1) = 2n − 1     (n ≥ 1)
```

Время **Θ(n)**, память **Θ(n)** (словарь на n значений и глубина рекурсии n). Важно, что словарь передаётся в рекурсивные вызовы: если бы каждый вызов создавал свой `memo`, мемоизация не работала бы — именно это ловит проверка `C(n) ≤ 2n + 1` в `self_check`.

### 2.4. `hanoi` — Ханойские башни

Чтобы перенести n дисков, нужно перенести n−1 верхних на вспомогательный стержень, перенести самый большой диск и вернуть n−1 дисков поверх него:

```
M(0) = 0
M(n) = 2·M(n−1) + 1   →   M(n) = 2ⁿ − 1   →   Θ(2ⁿ)
```

(Проверка подстановкой: 2·(2ⁿ⁻¹ − 1) + 1 = 2ⁿ − 1.) Это число **оптимально**: самый большой диск должен сдвинуться хотя бы раз, а для этого все остальные n−1 дисков должны сначала уйти с него и потом вернуться — минимум 2·M(n−1) + 1 ходов. Глубина рекурсии n, память Θ(n) (без учёта списка ходов, который сам занимает Θ(2ⁿ)).

### 2.5. `DynamicArray` — динамический массив с удвоением

Массив хранит буфер фиксированной **ёмкости** (capacity) и текущий **размер** (size). Пока есть место, `append` — одна запись, O(1). Когда буфер заполнен, выделяется новый вдвое больше и все size элементов копируются — Θ(n) для этой операции.

*Инвариант:* 0 ≤ size ≤ capacity; элементы буфера с индексами < size — данные, остальные — пустые ячейки.

**Амортизированный анализ** оценивает не худшую одиночную операцию, а **среднюю стоимость в худшей последовательности операций**. Отдельный `append` может стоить Θ(n), но такие операции редки, и их стоимость «размазывается» по дешёвым.

**Метод учёта (банковский метод).** Назначим каждому `append` цену **3 единицы**:
- 1 единица оплачивает запись самого элемента;
- 2 единицы откладываются «на счёт» этого элемента.

Пусть ёмкость удваивается с c до 2c. С прошлого расширения (с c/2 до c) было добавлено c/2 элементов, и каждый отложил 2 единицы — на счету **c единиц**. Копирование стоит ровно c (переносятся c элементов). Счёт никогда не уходит в минус, значит, суммарная стоимость n операций **не больше 3n**, и амортизированная стоимость `append` — **O(1)**.

**Точная стоимость.** При начальной ёмкости 4 копирования происходят при переходах 4 → 8 → 16 → … → C, где C — наименьшая степень двойки, не меньшая n. Перенесено 4 + 8 + … + C/2 = C − 4 элементов. Стоимость на операцию:

```
(n + копирования) / n = 1 + (C − 4) / n
```

Так как n ≤ C < 2n (C — ближайшая степень двойки сверху), величина лежит в интервале (2; 3), **строго меньше 3** — это и есть граница метода учёта.

**Почему у соседних 2ᵏ и 2ᵏ + 1 стоимость различается почти на 1.** При n = 4 096 = 2¹² буфер заполнен **ровно**, расширения до 8 192 ещё не было: C = n, стоимость 1 + 4 092/4 096 ≈ **2,0**. При n = 4 097 один лишний элемент вызывает расширение и копирование 4 096 элементов: C = 2n − 2, стоимость ≈ **3,0**. Один `append` добавляет к общей стоимости ≈ n единиц, то есть ≈ 1 на каждую операцию. Это худший момент для «среднего» — сразу после расширения, пока на счёт ещё ничего не накоплено.

Сжатие при `pop` не реализовано (оно необязательно); если реализовывать, сжимать вдвое нужно при size ≤ capacity/4, а не capacity/2: иначе чередование `append` и `pop` на границе вызывало бы расширение и сжатие на каждой операции — Θ(n) на операцию.

### 2.6. `Stack` — стек на динамическом массиве

Стек (LIFO, «последним пришёл — первым ушёл») использует только конец массива:

| Операция | Реализация | Сложность |
| --- | --- | --- |
| `push` | `DynamicArray.append` | O(1) амортизированно (Θ(n) в момент расширения) |
| `pop` | `DynamicArray.pop` | O(1) |
| `peek` | `get(size − 1)` | O(1) |

Конец массива выбран потому, что добавление и удаление там не требуют сдвига других элементов.

### 2.7. `Deque` — дек на двусвязном списке

Дек (двусторонняя очередь) поддерживает вставку и удаление с обоих концов. Каждый узел хранит значение и ссылки на соседей; дек хранит ссылки на первый (`head`) и последний (`tail`) узлы. Любая операция на конце меняет константное число ссылок, поэтому все четыре операции стоят **O(1) в худшем случае — без амортизации** (в отличие от `push` стека).

*Инвариант:* head = None ⇔ tail = None ⇔ size = 0; у head нет предыдущего, у tail — следующего узла; прямой и обратный обход дают одни и те же элементы.

Самое хрупкое место — переход к пустому деку и обратно: при удалении последнего узла нужно обнулить **и** head, **и** tail. Ошибка проявляется только на сочетаниях вида «push_front, pop_back, push_back, pop_front», поэтому `check_deque` перебирает все 16 таких сочетаний.

Плата за O(1) — память: на каждый элемент отдельный объект-узел с двумя ссылками.

### 2.8. Почему `list.insert(0, x)` и `list.pop(0)` — Θ(n)

`list` в CPython — динамический массив указателей, расположенных подряд в памяти. Вставка в начало требует сдвинуть все n указателей на одну позицию вправо, удаление из начала — влево: **Θ(n)** на операцию. `collections.deque` устроен как двусвязный список **блоков** по 64 элемента: операции на концах меняют только крайний блок — **O(1)**.

## 4. Сопоставление теории и эксперимента

### 4.1. Рекурсия: формулы числа вызовов подтверждены точно

Таблица 3.1 совпадает с формулами 2·F(n+1) − 1 и 2n − 1 без единого расхождения. При n = 30 наивная рекурсия делает 2,7 млн вызовов против 59 у мемоизированной — разница в 45 000 раз, и она растёт экспоненциально. Мемоизация превращает дерево вызовов в цепочку: каждая подзадача решается один раз.

### 4.2. Амортизированная стоимость append

Измеренная величина (n + копирования)/n лежит в диапазоне **1,999 … 2,999** — всегда ниже границы 3 метода учёта (график `lab02_append.png`, правая панель). Пара 4 096 / 4 097 из данных варианта показывает скачок ровно на 1 (1,999 → 2,999), как и предсказано в 2.5: один лишний элемент запускает копирование 4 096 элементов.

Время на операцию t/n при этом **не растёт с n**: 1,05–2,3·10⁻⁷ с для `DynamicArray` и 2,3–4,2·10⁻⁸ с для `list` на диапазоне в 100 раз — экспериментальное подтверждение амортизированного O(1). Колебания t/n частично повторяют колебания стоимости: самые дорогие точки по времени (2 059 и 132 277) — те, у которых стоимость близка к 3. Повышенное время на самых малых n дополнительно объясняется фиксированными накладными расходами на создание объекта и прогрев.

### 4.3. Операции у начала: наклон ≈ 1 против ≈ 0

В осях log-log наклон равен показателю степени (lg t = k·lg n + lg C).

- `list.insert(0, x)` и `list.pop(0)` — наклоны **0,95** и **1,09**, то есть время растёт линейно с размером: сдвиг всех n указателей массива. При n = 100 000 одна такая операция стоит 12–20 мкс — в **300–500 раз** дороже операции на конце дека.
- `collections.deque` и свой `Deque` — наклоны **0,00–0,04**: время одной операции не зависит от размера, O(1). Единичный выброс у `Deque.push_back + pop_front` при n = 30 000 (4,18·10⁻⁷ при соседних 2,5·10⁻⁷) — шум (сборщик мусора или фоновая активность ОС): точки по обе стороны лежат на одном уровне.

График `lab02_front.png`: линии `list` идут вверх под углом 45°, линии деков горизонтальны.

### 4.4. Откуда постоянный множитель ×3,4–3,6 при одинаковой асимптотике

Асимптотика операций своих структур и стандартных одинакова — O(1), но время различается в 3–4 раза (а у операций у начала — в 7 раз: 2,6·10⁻⁷ против 3,7·10⁻⁸). Big-O не учитывает константы, а они здесь разные:

- **Интерпретатор против C.** `list` и `collections.deque` реализованы на C: одна операция — несколько машинных инструкций. Своя структура — Python-код: каждый вызов метода, чтение атрибута (`self._size`, `self._buffer`), сравнение и присваивание исполняются интерпретатором байт-кода.
- **Слои вызовов.** `Stack.push` вызывает `DynamicArray.append` — два Python-вызова на операцию вместо одного вызова C-функции.
- **Выделение памяти.** Свой `Deque` создаёт отдельный объект `_Node` на **каждый** элемент (и сборщик мусора потом его освобождает), `collections.deque` выделяет память блоками по 64 элемента.
- **Копирование.** `list` растёт через `realloc` и перемещает память одним блочным копированием, а `DynamicArray._grow` копирует элементы в Python-цикле.

Все эти факторы меняют **константу**, но не порядок роста — поэтому наклоны своих и стандартных структур совпадают.

- `factorial(n) = n!` для n = 0…20 (против `math.factorial`);
- `fib_naive` и `fib_memo` совпадают с таблицей Фибоначчи; число вызовов наивной версии не меньше F(20) (это действительно наивная рекурсия), мемоизированной — не больше 2n + 1 (`memo` передаётся в рекурсию);
- Ханойские башни: ходов ровно 2ⁿ − 1; проигрывание ходов на модели стержней — больший диск ни разу не кладётся на меньший, в конце все диски на целевом стержне, имена стержней передаются правильно;
- `DynamicArray`: 0 ≤ size ≤ capacity; после каждого из 100 append ёмкость равна ближайшей степени двойки (не меньше 4), счётчик копирований равен C − 4; сжатие допустимо только вдвое и при size ≤ capacity/4;
- `Stack`: порядок LIFO через границы ёмкости 4, 8, 16, повторное использование после опустошения;
- `Deque`: согласованность head/tail при опустошении — все 16 сочетаний операций на одном элементе.

### Шаг 2. Репрезентативные тесты

- **граничные:** пустые структуры (`pop`, `peek`, `get`, `set` → `IndexError`), индексы −1, size, capacity − 1, capacity; n = 0 для рекурсивных функций;
- **вырожденные:** опустошение до нуля и повторное наполнение;
- **типовые:** случайные серии из 3 000 (стек) и 5 000 (дек) операций с частыми опустошениями;
- **данные варианта:** все 100 000 операций из `ops_stack.txt` и `ops_deque.txt`.

### Шаг 3. Сравнение с эталоном

Каждая операция случайных серий и файлов варианта выполнялась одновременно над своей структурой и эталоном (`list` для стека, `collections.deque` для дека) со сверкой результата **и размера** после каждой операции. Расхождений нет — `self_check: OK`.

### Шаг 4. Оценка сложности

Аналитические оценки раздела 2 подтверждены: точными формулами числа вызовов (4.1), стоимостью append < 3 и постоянным t/n (4.2), наклонами ≈ 1 для `list` у начала и ≈ 0 для деков (4.3).

### Вывод о применимости

**Принять.** Реализации корректны и соответствуют заявленной асимптотике; разница с встроенными структурами — постоянный множитель, объяснённый реализацией на интерпретируемом Python.

## 6. Выводы

1. Наивная рекурсия Фибоначчи экспоненциальна: ровно 2·F(n+1) − 1 вызовов, рост ≈ φⁿ. Мемоизация сводит её к 2n − 1 вызовам — Θ(n). При n = 30 разница в 45 000 раз.
2. Ханойские башни требуют ровно 2ⁿ − 1 ходов, и меньше нельзя; факториал — n + 1 вызов. Память рекурсии равна её глубине: Θ(n) у всех рассмотренных функций.
3. Динамический массив с удвоением даёт амортизированно O(1) на append: метод учёта с ценой 3 доказывает границу, измерения дают 2,0–3,0 элементарных действия на операцию. Скачок стоимости между 4 096 и 4 097 элементами (1,999 → 2,999) — момент расширения буфера.
4. Дек на двусвязном списке выполняет все операции на концах за O(1) в худшем случае; `list.insert(0, x)` и `list.pop(0)` — Θ(n) из-за сдвига элементов (наклоны 0,95 и 1,09 против 0,00–0,04).
5. При одинаковой асимптотике собственные структуры в 3,4–3,6 раза медленнее стандартных: интерпретация Python-кода, лишние слои вызовов и выделение узлов по одному меняют константу, но не порядок роста.
